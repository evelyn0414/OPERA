# **A-SINE (Artifactual and Soundscape In-the-wild Noise Emulation)**

`A-SINE` is a synthetic evaluation dataset designed to measure the robustness of audio models to two distinct categories of real-world acoustic interference:

- **Ambient Noise** from environmental soundscapes.
- **Sonic Artifacts** from device interaction and hardware failure. It is generated by applying a structured protocol of augmentations to a clean source corpus.

All ambient noise injection and artifact simulation are performed using the **`AugLy`** library for reproducibility.


## 1. Audio Corpora

### Original Signal Corpus (Clean)
- **Source:** Clinically gathered various respiratory and cardiac sounds datasets used in OPERA benchmark.
- **Processing:** All audio is resampled to **16000 Hz** to match typical model inputs.
- **Splitting:** The datasets are split into training, validation, and test sets using datasets' own splits.

### Ambient Noise Corpus
- **Source:** FSD50k (Freesound Dataset 50k).
- **Processing:** All audio is resampled to **16000 Hz** to match typical model inputs.
- **Selection:** The corpus is filtered to include only labels representing **continuous, ambient background sounds** (e.g., `Rain`, `Traffic noise`, `Mechanical fan`) the full list of included labels can be found under `dataset/fsdk50k_vocab.csv`. Transient and high-salience sounds (e.g., `Gunshot`, `Siren`, `Speech`) are explicitly excluded. All selected recordings have a minimum duration of **4 seconds** to ensure a consistent ambient sound texture.

## 2. Noise Generation Protocols

### `A-SINE-Ambient` Generation
- **Objective:** To simulate a model's performance in various environmental soundscapes.
- **Procedure:** For each clean signal, a noise sample is randomly selected from the curated FSD50k corpus. The noise is looped to match the signal's duration and mixed using `augly.audio.AddBackgroundNoise` at predefined Signal-to-Noise Ratios (SNR).
- **Levels:** Four distinct difficulty levels are defined by SNR.

    | Difficulty | SNR (dB) | Description |
    |------------|----------|-------------|
    | Mild | 40 dB | Noise is barely perceptible. |
    | Moderate | 30 dB | Noise is audible but not distracting. |
    | High | 20 dB | Noise is prominent and challenging. |
    | Severe | 10 dB | Noise significantly obscures the signal. |

### `A-SINE-Artifact` Generation
- **Objective:** To simulate common device handling errors, hardware limitations, and software-induced distortions.
- **Procedure:** For each clean signal, a single artifact function is randomly selected and applied. Each function has it's own predefined parameter sets corresponding to "Mild" and "Severe" intensity levels.
- **Transform Functions:** The artifacts and their corresponding `AugLy` implementations are detailed below.

    | Effect | Parameters | Real-world Simulation |
    | --- | --- | --- |
    | AddBackgroundNoise | - background_audio: None, snr_level_db=40.0 | Cheap ADC may result in white noise | 
    | ChangeVolume + PeakingEqualizer | - volume_db: 8<br>- center_hz: 120, q: 0.7, gain_db: 12<br>- center_hz: 150, q: 1.0, gain_db: 6 | Microphone placed too close to chest wall, causing bass boost and resonance |
    | Reverb + HighPassFilter | - reverberance: 60, room_scale: 40.0<br>- cutoff_hz: 150 | Recording in a large, empty room with a distant microphone |
    | LowPassFilter | - cutoff_hz: 500 | Poor quality or supressed microphone |
    | PeakingEqualizer | - center_hz: 8000, q: 2, gain_db: -6 | Muffled recording due to clothing or improper sensor contact |
    | Harmonic | - kernel_size: 31, power: 2, margin: 1.5 | Simple noise suppression |
    | PitchShift | - n_steps: 5 | Digital sampling rate mismatch or clock drift |
    | Percussive | - kernel_size: 31, power: 2, margin: 1 | Impact noise from device handling or patient movement |
    | TimeStretch | - rate: 1.5 | Network jitter in streaming |
    | Tempo | - factor: 1.5 | Audio playback speed inconsistency |
    | Clicks + ApplyLambda | - seconds_between_clicks: 0.3<br>- aug_function: lambda audio, sr: F.zero_out_chunks(audio, sr, p=0.05, chunk_len_ms=20) | Corrupted packets sounding like Clicks, and lost packets creating silent gaps


# **Evaluation Protocol**
This benchmark defines a standardized protocol for quantifying the robustness of foundation audio models when subjected to realistic ambient noise and sonic artifacts. The evaluation framework is designed to measure both classification and regression performance degradation under noisy conditions, using 19 diverse tasks adapted from the OPERA benchmark.

## 1. Benchmark Tasks
**Total Tasks:** 19, each corresponding to a distinct dataset.
  - **Tasks 1–12:** Disease detection (classification) tasks.
  - **Tasks 13–19:** Lung function estimation (regression) tasks.

## 2. Evaluation Protocol
1. A foundation model is pre-trained on clean data.

2. For each task, **five independent classification or regression heads** are trained on top of the frozen foundation model, each initialized with a different random seed (total: 5 seeds per task).

3. All heads are trained **only on the clean version** of the dataset.

4. For each head/seed, a **noisy test set** is generated by randomly selecting noise files, ensuring that each seed sees a different noisy realization. Heads are evaluated on these noisy test sets.

5. Results from the five seeds are averaged to account for random initialization and noise selection variability.


## 3. Performance Metrics
- **For Classification Tasks (Tasks 1–12):** Mean Area Under the ROC Curve (AUC) across 5 seeds.

- **Regression Tasks (Tasks 13–19):** Mean Mean Absolute Error (MAE) across 5 seeds.


## 4. Key Differences from OPERA Benchmark
- **Test Set Generation:**
  Unlike OPERA, for each training seed, a unique noisy test set is generated by randomly sampling noise files, ensuring variability and robustness in evaluation.

# **Usage & Reproducibility**
## 1. Folder Structure
```
OPERA/
│
├── aug/                  # Augmentation code, configs, and utilities
│   ├── augment/          # Augmentation modules
│   ├── data/             # Data-related scripts/utilities
│   ├── scripts/          # python scripts for generating datasets
│   ├── tools/            # Additional tools/utilities
│   ├── utils.py          # Utility functions for augmentation
│   └── config.py         # Configuration management
│
├── scripts/              # Top-level evaluation and feature extraction scripts
│   ├── eval_*.sh         # Evaluation scripts for different datasets/tasks
│   ├── extract_features*.sh # Feature extraction scripts
│   └── ...               # Other helper scripts
│
├── config_*.yaml         # Dataset-specific configuration files
└── ...                   # Rest of the project files (pre-training, etc.)
```


## **2. Environment Setup**
The environment can be created by running:
```
git clone https://github.com/evelyn0414/OPERA.git
cd ./OPERA

conda env create --file environment.yml
sh ./prepare_env.sh
source ~/.bashrc

conda init
conda activate audio
sh ./prepare_code.sh
```
*After installation, next time to run the code, you only need to acivate the audio env by `conda activate audio`.


## **3. Dataset Preparation and Configuration**
1. First obtain the clean datasets by running the following

    ```
    #TODO:
    sh ./download_datasets_all.sh
    ```

2. Each dataset/task has a corresponding YAML config (e.g., `config_icbhidisease.yaml`, `config_copd.yaml`).

    **Example:**
    ```yaml
    output_path: "/your/desired/noisy_dataset/storage/path/"
    generator_settings:
      clean_sample_prob: 0.2
      artefact_prob: 0.3
      ambient_noise_prob: 0.5
    noise_level: [20, 30, "inf"] # noise levels in dB SNR. "inf" indicates clean samples"
    random_seed: 42
    ```

## **4. Running Evaluation**
Use the provided shell scripts in `scripts/` to launch evaluations for each task. Example for ICBHI:

```bash
bash scripts/eval_icbhi.sh
```
- These scripts will:
  - Load the dataset config file
  - Prepare the dataset (with/without augmentation)
  - Run the evaluation protocol

If you want to generate a custom noisy dataset run the following from the project root:
```
python -u aug/scripts/generate_test_set --config config_DATASETNAME.yaml
```
This will generate a noisy dataset with specified `generator_settings` under `output_path`, both specified inside `config_DATASETNAME.yaml`


## **5. Customization**
- **To change augmentation frequency:**
  Edit `generator_settings` in the config YAML.

- **To evaluate on new datasets:**
  1. Create a new feature extraction script for your dataset and save under `src/benchmark/processing/`.

  2. Create a new evaluation function inside `benchmark/linear_eval_noisy.py` script.
  
  3. Create the dataset config YAML file.
  
  4. Create and save the new evaluation script under `scripts/`
